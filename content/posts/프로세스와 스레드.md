## **📌 Part 1. Process & Thread 기본 개념**

### 1. 프로세스(Process)

- 프로세스의 정의
    - 실행 중인 프로그램
    - 운영체제로부터 독립적인 메모리 공간과 시스템 자원을 부여받는 실행 단위
- 프로세스 구조
    - **Code**: 실행할 명령어
    - **Data**: 전역 변수
    - **Heap**: 동적 메모리
    - **Stack**: 함수 호출 스택

## 📱 모바일 시점의 멀티 프로세스 예시

### iOS

- 기본적으로 멀티 프로세스를 거의 사용하지 않음
- WebKit(WebView)은 별도 프로세스로 실행됨

### Android

- 멀티 프로세스를 자주 사용
    - 예: 메신저 앱의 메시지 처리 서비스
    - 무거운 컴포넌트 분리
- manifest 에 `<service android:process=":remote"/>` 로 바로 분리 가능

### Flutter

- Flutter 코드(Dart)는 보통 하나의 프로세스에서 실행
    
- 멀티 프로세스를 쓰려면 플랫폼(Android/iOS)단에서 구현해야 함
    
    → Flutter 자체적으로 멀티프로세싱 옵션은 없음

### 2. 멀티 프로세스(Multi Process)

- 정의
    - 여러 프로세스를 동시에 실행하는 것
- 장점
    - 프로세스 간 완전한 격리
    - 하나가 죽어도 다른 프로세스 영향 없음
    - 보안 강함
- 단점
    - 메모리 많이 씀
    - Context Switching 비용 높음
    - IPC로 통신해야하므로 복잡

### 3. 스레드(Thread)

- 스레드의 정의
    - 프로세스 내부에서 실행되는 작은 실행 단위
    - 하나의 프로세스 안에서 여러 개의 스레드를 띄울 수 있음
- 공통 개념
    - Code, Data, Heap 공유
    - Stack 개별 할당
    - 스레드 생성은 프로세스보다 빠르고 가벼움

## 모바일 OS별 스레드 모델

### ✔️ iOS

- 앱 실행 시 기본적으로 **main thread(UI thread)** 와
    
    **여러 background thread(GCD, OperationQueue)**
    
- 스레드 관리 API가 매우 강력하고 단순함
    
    → GCD(DispatchQueue)가 핵심
    

### ✔️ Android

- Java/Kotlin 기반 스레드 모델
- **main thread(UI)** + 여러 background thread
- Coroutine, ThreadPoolExecutor, HandlerThread 등 선택 다양

### ✔️ Flutter(Dart)

- Dart는 스레드 기반이 아니라 **Isolate 기반**
    - 각 Isolate는 독립적인 메모리 공간
    - 메모리를 공유하지 않고 메시지로 통신
- JS의 Web Worker와 유사
- UI는 **메인 Isolate**에서만 접근 가능

❗ “Flutter에서 멀티스레딩”이라 말하지 않고

→ “Flutter에서 멀티 Isolate”라고 표현함.

---

### 4. 멀티 스레드(Multi Thread)

- 정의
    - 하나의 프로세스 내에서 여러 스레드가 동시에 실행되는 구조
- 장점
    - CPU 활용 증가
    - 병렬 처리가능
    - 프로세스보다 메모리 덜 사용
- 단점
    - 데이터 공유 → Race Condition 발생
    - 동기화 필요
    - 디버깅 난이도 증가

## 모바일 OS의 멀티스레드 활용 포인트

### ✔️ iOS

- GCD로 concurrency 쉽게 처리
- main thread blocked → UI freeze
- 동기화 신경 써야 함

### ✔️ Android

- Coroutine으로 비동기 처리
- ThreadPool 구성 다양
- main thread blocking 시 ANR(Application Not Responding) 발생

### ✔️ Flutter

- UI Isolate는 항상 단독
- heavy 작업은 **별도 Isolate**로 분리
- 중간에서 메시지 passing 필요

### 5. 멀티 프로세스 vs 멀티 스레드 비교

|구분|멀티 프로세스|멀티 스레드|
|---|---|---|
|메모리|독립|공유|
|안정성|매우 높음|낮음|
|성능|느림|빠름|
|모바일 iOS|WebKit 등 일부만|GCD 중심|
|모바일 Android|서비스 분리에 자주 사용|Coroutine + Thread|
|Flutter|플랫폼 차원에서 사용|Dart는 Isolate 모델|

## **📌 Part 2. 동기화(Synchronization) & 문제 해결**

### 6. 동기화가 필요한 이유
- **Race condition**
    - **여러 스레드가 같은 자원에 동시에 접근**하면서 side effect를 만드는 상황
    - iOS 
    	- 여러 스레드가 동시에 같은 배열에 append -> crash 가능 
    	- 한 스레드가 이미지 다운로드 중인데 다른 스레드가 메모리 해제 -> 접근 오류 
    - Android
    	-  여러 Coroutine 또는 Thread가 SharedPreferences를 동시에 수정
    	- 동일 객체를 여러 스레드가 변경 → 이상한 UI 상태로 업데이트 
    - Flutter
    	- isolate 간 메모리를 공유하지 않지만, 같은 isolate 내 async 작업 간 순서 보장 X -> async race 발생 가능 

- **Critical Section**
	 여러 실행 흐름이 동시에 접근하면 안 되는 코드 영역 이 영역은 동시에 오직 하나만 실행돼야 한다. 
	- ex - 은행 계좌 잔액 변경, 리스트에 아이템 추가 / 삭제

### 7. Mutex 

- 정의
	- Mutual Exclusion(상호 배제)의 약자 
	- 한 시점에 오직 하나의 스레드만 임계 구역을 실행할 수 있도록 막는 장치 
- Locking 방식
	- lock(): 스레드가 임계 구역에 접근할 때 lock 획득 
	- unlock(): 작업 끝나면 잠금 해제 
	- waiting: 이미 누군가 lock 을 잡고 있을때 

**✔ iOS**
- NSLock
- pthread_mutex
- DispatchSemaphore(value: 1) → 세마포어지만 **뮤텍스처럼 사용**
``` swift
let lock = NSLock()
lock.lock()
criticalWork()
lock.unlock()
```
 **✔ Android**
- synchronized keyword
- ReentrantLock
- Mutex(Kotlin Coroutines)
``` kotlin
mutex.withLock {
    // critical section
}
```

**✔ Flutter**
Flutter는 메모리를 공유하는 스레드가 없기 때문에 **뮤텍스 개념 없음**
하지만,
- 한 Isolate 내부에서 async 작업 순서 보장은 할 수 있어야 해서 async lock 패턴을 구현하기도 함
    예: async_mutex package


### 8. Semaphore (세마포어)

- 정의
	- 스레드 접근을 카운트 기반으로 제어하는 동기화 도구 (정해진 인원만 들어올 수 있는 문 ) 
- 종류 
	- Binary Semaphore
	  값이 0 또는 1 사실상 Mutex 와 유사 
	  하나의 스레드만 접근 가능 
	- Counting Semaphore
	  값이 N 
	  동시에 N개의 스레드가 임계 구역 접근 가능 

  
 **✔ iOS**
- DispatchSemaphore 활용
``` swift
let sema = DispatchSemaphore(value: 3) // 최대 3개 동시
sema.wait()
// critical section
sema.signal()
```

사용 예:
- 병렬 이미지 다운로드 5개만 허용
- API 호출 rate limit 제어
- 비동기 함수 동기화

 **✔ Android**
- Semaphore 클래스
``` kotlin  
val sem = Semaphore(3)
sem.acquire()
// critical section
sem.release()
```
사용 예:
- ThreadPool이 너무 많은 작업을 동시 실행하지 않도록 제한
- DB connection pool 크기 제어

**✔ Flutter**
  
Flutter의 Isolate는 메모리 공유가 없기 때문에 전통적인 세마포어는 없음.
하지만 플랫폼 채널에서 네트워크/DB 등 공유 자원 접근 시 플랫폼(iOS/Android)에서 세마포어를 쓴다.
### 9. Deadlock
- 정의
	- 여러 스레드가 서로가 가진 자원을 기다리며 영원히 대기에 빠지는 것 
	- A는 B의 unlock 을 기다리고 B도 A 의 unlock 을 기다리는 상황 
- 발생 조건 
	- **상호 배제 (Mutual Exclusion)** — 자원은 동시에 하나만
	- **점유와 대기 (Hold and Wait)** — 하나 점유한 채 다른 자원 대기
	- **비선점 (No Preemption)** — 다른 스레드 자원 강제로 뺏기 불가
	- **원형 대기 (Circular Wait)** — A→B→C→A 식의 순환
